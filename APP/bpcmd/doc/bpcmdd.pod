=head1 NAME

bpcmdd - Bundle Protocol command daemon

=head1 SYNOPSIS

B<bpcmdd> [B<-n>] [B<-t> I<ttl>] I<ownEndpointID> I<whitelistFile>

=head1 DESCRIPTION

B<bpcmdd> listens on the BP endpoint I<ownEndpointID> and treats each
delivered bundle's payload as a command line.  It tokenises the payload on
whitespace, checks the resulting command against the rules in
I<whitelistFile>, and, if the command is permitted, execs it directly (with
no intervening shell) and, unless B<-n> is given, returns whatever the
command writes to its standard output back to the bundle's source endpoint
ID as a reply bundle.

Because the command is exec'd directly from the tokenised payload, shell
metacharacters (C<;>, C<|>, C<$()>, backticks) are inert: they become
literal arguments and can do nothing unless a whitelist rule explicitly
permits a shell.  The command is run with an empty standard input.

One child process is spawned per bundle (fork-per-bundle), and bundles are
processed serially: a long-running command blocks reception of the next
bundle until it exits.

The command is invoked with these environment variables set:
B<BP_SOURCE_EID> (the received bundle's source EID) and B<BP_DEST_EID>
(I<ownEndpointID>).  The command's standard error is inherited and appears
on B<bpcmdd>'s standard error.

A command that is not permitted by the whitelist is not run; instead a
C<command not permitted> reply is returned to the source (unless B<-n>).
No reply is sent when B<-n> is in effect, when the bundle source is the
anonymous EID B<dtn:none>, or when a permitted command produces no standard
output.

B<bpcmdd> runs until it receives SIGINT, at which point it detaches from BP.

=head1 WHITELIST FILE

I<whitelistFile> holds one rule per line; blank lines and lines beginning
with C<#> are ignored.  Each rule has the form C<[mode] pattern>, where the
optional I<mode> keyword is one of:

=over 4

=item B<exact>

I<pattern> is a literal string, matched against the whole command line.

=item B<glob>

I<pattern> is a shell-style wildcard using C<*> and C<?>.

=item B<regex>

I<pattern> is a POSIX extended regular expression.  This is the default
when the mode keyword is omitted.

=back

Every rule is anchored: it must match the entire normalised command line
(the argument tokens rejoined with single spaces), so a rule for C<gpio>
cannot authorise C<gpionuke>.  A command runs if it matches any rule.  A
whitelist that is empty or cannot be read denies every command.

=head1 EXIT STATUS

=over 4

=item "0"

B<bpcmdd> terminated normally after receiving SIGINT.

=item "1"

B<bpcmdd> terminated due to a usage error, an unreadable or malformed
whitelist, or a startup or BP failure.  Details are noted in the
B<ion.log> log file.

=back

=head1 OPTIONS

=over 4

=item B<-n>

Do not send any reply (neither command output nor refusal notices) back to
the bundle source.

=item B<-t> I<ttl>

Reply bundle lifetime, in seconds.  Defaults to 86400.

=item B<-a> I<eidlist>

Act only on bundles whose source EID matches one of the comma-separated glob
patterns in I<eidlist> (for example C<ipn:1.*,ipn:2.3>); bundles from any other
source are ignored.  The patterns use shell wildcards (B<*>, B<?>).  Optional;
when omitted, bundles from any source EID are accepted.  Because a source EID
can be spoofed, this filter is only meaningful when combined with BPSec (see
B<SECURITY>).

=item B<-u> I<user>

Run every command as I<user> (a login name or numeric UID) instead of the user
B<bpcmdd> was started as; its primary and supplementary groups are set as well.
B<bpcmdd> must start with sufficient privilege (typically as root) to change
identity.  Optional; when omitted, commands run as the daemon's own user.

=item I<ownEndpointID>

The local endpoint ID on which B<bpcmdd> listens.  Mandatory.

=item I<whitelistFile>

Path to the whitelist file governing which commands may run.  Mandatory.

=back

=head1 FILES

I<whitelistFile>, as described under B<WHITELIST FILE>.

=head1 DIAGNOSTICS

The following diagnostics may be issued to the B<ion.log> log file:

=over 4

=item bpcmdd can't attach to BP.

B<bpadmin> has not yet initialized Bundle Protocol operations.

=item bpcmdd can't open own endpoint.

Another application has already opened I<ownEndpointID>.  Terminate that
application and rerun, or choose a different endpoint.

=item bpcmdd can't load whitelist.

I<whitelistFile> could not be opened or contains a malformed regular
expression.  Correct the file and rerun.

=item bpcmdd denied command

An incoming command line did not match any whitelist rule and was refused.
The offending command line is noted with the message.

=item bpcmdd can't fork command.

System error.  Check for earlier diagnostic messages describing the cause of
the error; correct problem and rerun.

=item bpcmdd can't send reply bundle.

System error.  Check for earlier diagnostic messages describing the cause of
the error; correct problem and rerun.

=back

=head1 SECURITY

B<bpcmdd> runs commands on behalf of any node that can deliver a bundle to
I<ownEndpointID>.  Two controls stand between a sender and code execution: the
whitelist, which fixes exactly what may run, and the source of the bundle,
which fixes who may ask.  The whitelist is the primary defence and should be as
narrow as possible; execution is direct (no shell), so shell metacharacters in
a payload are inert.  Use B<-a> to additionally restrict which source EIDs are
served.  A bundle source EID is trivially spoofable unless the bundles are
authenticated by BPSec, so B<-a> is a meaningful control only when B<bpcmdd> is
run over links protected by BPSec; do so for any deployment where the command
set is not safe for arbitrary callers.

Use B<-u> to run commands under a dedicated unprivileged identity, then bound
that identity's reach with the target machine's own permission mechanics (file
ownership and modes, sudoers, and the like) rather than relying on B<bpcmdd>
alone.
